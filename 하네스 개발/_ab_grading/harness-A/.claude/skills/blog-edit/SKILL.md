# Blog Edit — 편집·교정 & 발행 패키징

blog-editor 에이전트가 초안을 발행 가능한 최종본으로 완성할 때 따르는 절차. editor는 품질의 최종 관문이다.

## 왜 양쪽을 동시에 읽는가
초안과 출처 파일을 각각 따로 보면 "출처가 존재하는가"만 확인하게 된다. 진짜 결함은 경계면에 있다 — 본문이 출처보다 과장된 주장을 하거나(over-claim), 출처가 뒷받침하지 않는 문장이 섞이는 경우다. 본문의 [Sx] 표시와 sources 원문을 **동시에** 펼쳐 대조해야 이런 불일치를 잡는다.

## 절차

### 1. 출처 교차 검증 (최우선)
`_workspace/02_writer_draft.md`와 `_workspace/01_researcher_sources.md`를 함께 읽고, 본문의 각 [Sx] 표시에 대해:

| 검증 항목 | 확인 방법 |
|----------|----------|
| 출처 존재 | [Sx] ID가 sources 파일에 실재하는가 |
| 사실 일치 | 본문 주장이 해당 출처의 핵심 사실과 일치하는가 (과장 없는가) |
| 인용 누락 | sources의 중요한 사실인데 본문에 출처 표시가 빠지지 않았는가 |

불일치를 발견하면 직접 사실을 고치지 말고 writer/researcher에게 구체적 수정 지시(문장 + 사유 + 방향)를 보낸다. 양쪽 경계 이슈는 둘 다에게 알린다. 최대 2회 요청 후에도 미해결이면 해당 주장을 약화/제거하고 보고서에 명시한다 (무한 루프 방지).

### 2. 문체·교정
의미를 보존하며 표현만 다듬는다:
- 맞춤법·문법·오탈자 교정
- 중복·군더더기 제거, 긴 문장 분할
- 단락 흐름과 소제목 일관성 점검
- 저자의 사실 주장은 바꾸지 않는다 (역할 경계)

### 3. SEO 제목 & 메타설명
- 제목: 핵심 키워드를 앞쪽에 포함, 클릭 유도하되 과장(낚시) 금지
- 메타설명: 150~160자. 검색 결과에서 글의 가치를 한눈에 전달, 키워드 포함

### 4. 출처 목록 변환
본문의 [Sx] 표시를 모두 제거하고, 글 하단에 정식 "출처" 목록(번호 + 제목 + URL/출처)으로 변환한다. 본문에서 실제 인용된 출처만 목록에 넣는다.

### 5. 발행 패키징 & 자체 점검
`_workspace/03_editor_final.md` 형식:
```
---
제목: {SEO 최종 제목}
메타설명: {150~160자}
---

{교정된 본문 — [Sx] 표시 제거}

## 출처
1. {출처 제목} — {URL/출처}
2. ...
```

발행 전 확인:
- 제목·메타설명·본문·출처 4요소가 모두 존재하는가?
- 본문에 [Sx] 같은 내부 표시가 남아있지 않은가?
- 출처 목록의 모든 항목이 본문에서 실제로 쓰였는가?
- 메타설명이 150~160자인가?

## 후속 작업 (재실행)
최종본이 존재하고 사용자가 부분 수정(예: "제목만 다시", "메타설명 줄여")을 요청하면 해당 부분만 고치고 나머지는 보존한다. 초안이 갱신되었으면 변경 섹션만 재교정한다.
