# Blog Research — 리서치 및 개요 설계

블로그 글 한 편의 토대를 만드는 스킬이다. 주제/키워드를 받아 **검증 가능한 사실·통계·출처**를 모으고, 그 위에 **섹션별 개요**를 얹어 작가가 곧바로 초안을 쓸 수 있는 산출물을 만든다. 리서치 없는 글은 주장만 남고, 개요 없는 리서치는 글이 되지 못한다 — 둘을 한 산출물에 묶는 것이 이 스킬의 핵심이다.

## 입출력 (경계면 — 정확히 지킬 것)

- **입력:** `_workspace/00_input/domain.md` + 오케스트레이터가 전달한 주제/키워드와 옵션(톤·대상 독자·목표 분량). 옵션이 비면 중립 톤·일반 독자·800~1200단어를 가정한다.
- **출력:** `_workspace/02_research_outline.md` — 이 한 파일에 리서치 노트 + 출처 목록 + 섹션별 개요를 모두 담는다. 이 파일은 blog-writer가 **유일한 입력**으로 읽으므로, 파일명과 경로를 글자 그대로 지킨다.

## 작업 순서

1. **주제 정규화.** 입력에서 핵심 주제, 타깃 키워드, 독자, 톤, 목표 분량을 추출해 한 줄로 명시한다. 모호하면 가장 일반적인 해석을 택하고 그 가정을 산출물 상단에 적는다 — 작가가 무엇을 전제로 한 리서치인지 알아야 한다.

2. **리서치 수집.** WebSearch/WebFetch가 가용하면 사용해 1차 사실·통계·전문가 견해를 모은다. 각 사실에는 반드시 출처(제목·URL·게시일 가능 시)를 붙인다. 출처 신뢰도·최소 출처 수 기준은 `references/research-checklist.md`를 따른다. **WebSearch 불가 시** 모델 지식으로 작성하되 해당 항목에 `[출처 미검증]`을 표기한다 — 작가와 편집자가 이를 보고 검증 여부를 판단한다.

3. **개요 설계.** 수집한 근거를 논리 흐름으로 배열해 표준 구조(제목 후보 2~3개 / 도입 / 본문 3~5섹션 / 결론)의 개요를 만든다. 각 본문 섹션에는 **그 섹션이 사용할 출처를 매핑**한다 — 근거 없는 섹션은 만들지 않는다. 구조 표준은 `references/research-checklist.md` 참조.

4. **자기 점검.** 산출 직전 체크리스트(`references/research-checklist.md`)로 출처 수·개요 완결성·미검증 표기를 확인한 뒤 `02_research_outline.md`로 저장한다.

## 산출물 구조 (`02_research_outline.md`)

```
# 리서치 & 개요: {주제}

## 전제
- 주제 / 타깃 키워드 / 독자 / 톤 / 목표 분량 / 가정한 기본값

## 리서치 노트
- 사실·통계·견해 (각 항목에 [출처 N] 또는 [출처 미검증])

## 출처 목록
- [출처 1] 제목 — URL — 게시일/매체
- ...

## 개요
### 제목 후보
1. ... 2. ...
### 도입 (훅 + 글이 다룰 범위)
### 본문 섹션 1: {소제목}  ← 사용 출처: [출처 a], [출처 b]
### 본문 섹션 2 ...
### 결론 (요약 + 독자 행동/마무리)
```

## 후속 작업 (재리서치·보완)

이미 `02_research_outline.md`가 있고 보완 요청을 받으면, **전체를 새로 쓰지 말고 해당 부분만 갱신**한다.

- "출처가 약하다 / 근거 부족" → 해당 섹션에 출처를 추가하고 출처 목록에 append. 다른 섹션은 그대로 둔다.
- "개요 구조를 바꿔라 / 섹션을 더 / 덜" → 개요만 재배열하고 리서치 노트는 보존한다.
- blog-writer 또는 blog-editor로부터 SendMessage로 "X 섹션 추가 근거 요청 / 사실 출처 보강 요청"을 받으면, 요청된 범위만 보강해 `02_research_outline.md`에 반영하고 요청자에게 완료를 통지한다.

## 팀 통신

- **발신:** 리서치·개요 완료 시 blog-writer에게 산출물 위치(`_workspace/02_research_outline.md`)를 통지한다.
- **수신:** blog-writer의 "근거 부족 섹션 추가 리서치 요청", blog-editor의 "사실 출처 보강 요청" → 해당 범위만 보강 후 회신.

## 상세 기준

출처 신뢰도 등급, 최소 출처 수, 개요 표준 구조의 세부는 `references/research-checklist.md`를 읽는다.
