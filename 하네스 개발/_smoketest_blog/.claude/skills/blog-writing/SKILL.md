# Blog Writing — 초안 작성

리서치·개요를 **읽히는 글**로 바꾸는 스킬이다. 좋은 초안은 새 사실을 지어내지 않는다 — 개요의 구조와 리서치의 출처에 충실하면서, 도입에서 끌어들이고 본문에서 설득하고 결론에서 남긴다. 초안의 품질이 편집 단계의 부담을 결정한다.

## 입출력 (경계면 — 정확히 지킬 것)

- **입력:** `_workspace/02_research_outline.md` — blog-researcher의 산출물. 이 한 파일이 유일한 입력이다. 여기 없는 사실은 본문에 넣지 않는다(환각 방지). 근거가 부족하면 만들지 말고 리서처에게 요청한다.
- **출력:** `_workspace/03_draft.md` — 제목 + 전체 본문 초안(출처 인용 포함). 이 파일은 blog-editor가 **유일한 입력**으로 읽으므로 파일명·경로를 글자 그대로 지킨다.

## 작업 순서

1. **개요 흡수.** `02_research_outline.md`의 전제(톤·독자·분량)와 개요·출처 매핑을 읽는다. 전제의 톤/독자/분량이 글 전체의 기준이 된다.

2. **제목 확정.** 제목 후보 중 하나를 고르거나 다듬어 확정한다 — 타깃 키워드를 앞쪽에 두고 과장은 피한다. 패턴은 `references/writing-guide.md` 참조.

3. **본문 작성.** 개요 순서대로 도입→본문 섹션→결론을 쓴다. 각 본문 섹션은 매핑된 출처를 본문 안에서 자연스럽게 인용한다(인용 표기법은 `references/writing-guide.md`). 톤·문단 길이·전환은 가이드를 따른다. 개요에 없는 새 주장은 넣지 않는다 — 필요하면 리서처에게 추가 근거를 요청한다.

4. **분량 맞춤.** 목표 분량에 수렴시킨다. 부족하면 예시·설명으로 보강하되 군더더기 반복은 피하고, 초과하면 곁가지를 쳐낸다.

5. **저장.** 출처가 본문에서 인용된 그대로 글 끝 "출처" 섹션에 정리해 `03_draft.md`로 저장한다.

## 산출물 구조 (`03_draft.md`)

```
# {확정 제목}

{도입 — 훅 + 글이 다룰 범위}

## {본문 섹션 1 소제목}
{내용 + 인용 [출처 N]}

## {본문 섹션 2 ...}

## 결론
{요약 + 마무리/행동 제안}

## 출처
- [출처 N] 제목 — URL — 매체 (02_research_outline.md에서 가져옴)
```

## 후속 작업 (재작성·수정·반려 대응)

이미 `03_draft.md`가 있거나 editor로부터 반려를 받으면, **전체 재작성이 기본 아님 — 요청 범위만 수정**한다.

- editor의 반려(SendMessage, 사유 포함) → 사유에 해당하는 섹션만 고쳐 `03_draft.md`를 갱신하고 editor에게 회신한다. 반려는 최대 1회이므로 사유를 정확히 반영한다.
- "결론만 다시 / 이 섹션만" → 해당 섹션만 교체하고 나머지는 보존.
- "더 길게/짧게" → 분량만 조정(핵심 주장·출처는 유지).
- "톤을 캐주얼하게/격식 있게" → 문체만 바꾸고 사실은 유지.
- 근거가 부족해 못 쓰는 섹션 → blog-researcher에게 추가 리서치를 요청하고, 회신받은 근거로 해당 섹션을 채운다.

## 팀 통신

- **발신:** 초안 완료 시 blog-editor에게 위치(`_workspace/03_draft.md`) 통지. 근거 부족 시 blog-researcher에게 추가 리서치 요청.
- **수신:** blog-editor의 "재작성/수정 반려 요청(사유 포함)" → 해당 범위 수정 후 회신. blog-researcher의 "추가 근거 회신" → 해당 섹션에 반영.

## 상세 기준

블로그 톤, 문단 길이, 인용 표기법, 제목 작성 패턴, 도입-본문-결론 구조의 세부는 `references/writing-guide.md`를 읽는다.
