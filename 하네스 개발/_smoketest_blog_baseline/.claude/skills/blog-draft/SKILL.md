# Blog Draft — 초안 집필

blog-writer 에이전트가 개요+출처를 본문 초안으로 확장할 때 따르는 절차.

## 왜 개요에 충실해야 하는가
개요는 출처에 묶인 검증된 뼈대다. 개요를 벗어나 새 사실을 추가하면 근거 없는 주장이 들어가 글 전체의 신뢰도가 무너진다. writer의 자유는 "표현"에 있지 "사실"에 있지 않다.

## 절차

### 1. 입력 흡수
- `_workspace/01_researcher_outline.md`로 구조와 각 섹션의 핵심 메시지를 파악
- `_workspace/01_researcher_sources.md`로 각 [Sx] ID가 가리키는 사실을 확인
- 개요의 "조사 한계"에 적힌 내용은 본문에서 다루지 않는다

### 2. 도입부 작성 (훅)
첫 2~3문장이 독자의 체류를 결정한다. 검색 의도를 즉시 건드리는 질문·통계·상황 제시로 시작한다. 핵심 키워드를 첫 단락에 자연스럽게 포함한다.

### 3. 본문 집필
개요의 각 섹션을 완결된 단락으로 확장한다:
- 한 단락 = 하나의 생각. 긴 문장보다 짧고 명료한 문장을 우선한다
- 사실을 서술한 직후 해당 출처 ID를 `[S1]` 형태로 본문에 남긴다 (editor가 정식 출처로 변환)
- 개요에 없는 사실 주장은 추가하지 않는다. 필요하면 researcher에게 출처를 요청한다
- 소제목(H2/H3)에 키워드를 자연스럽게 배치한다. 억지 반복은 가독성과 SEO를 모두 해친다

### 4. 마무리 작성
핵심을 1~2문장으로 요약하고, 독자가 다음에 할 행동(읽기/시도/공유)을 제시한다.

### 5. 자체 점검
- 모든 사실 문장에 [Sx] 표시가 있는가?
- 개요에 없는 새 사실을 넣지 않았는가?
- 톤·분량·키워드 요구를 충족하는가?

`_workspace/02_writer_draft.md` 형식:
```
# {제안 제목}

{도입부}

## {H2 섹션}
{본문, 사실 옆 [S1] 표시}

## 마무리
{요약 + 행동 유도}

---
사용한 출처 ID: [S1], [S2], ...
```

## 후속 작업 (재실행)
editor의 수정 지시가 있으면 기존 초안을 읽고 **지시받은 부분만** 수정한다. 통과된 섹션은 보존한다. 개요가 갱신되었으면 변경된 섹션만 다시 집필한다.

## 출력 요약
- `_workspace/02_writer_draft.md`
완료 시 editor에게 초안 경로를 SendMessage로 통지한다.
