# Blog Research — 리서치 & 개요 설계

blog-researcher 에이전트가 주제/키워드를 출처 기반의 구조화 개요로 변환할 때 따르는 절차.

## 왜 출처를 먼저 고정하는가
개요를 먼저 쓰고 나중에 출처를 끼워 맞추면 writer가 근거 없는 문장을 쓰게 된다. 출처를 먼저 ID로 고정하면, 개요의 모든 주장이 검증 가능한 사실에 묶인다.

## 절차

### 1. 검색 의도 파악
주제/키워드를 보고 다음을 한 문장씩 정한다:
- 타깃 독자 (초심자 / 실무자 / 의사결정자)
- 검색 의도 (정보형 / 비교형 / 방법형 / 거래형)
- 권장 톤·분량 (사용자 지정이 있으면 그것을 따른다)

검색 의도가 글의 구조를 결정한다. 방법형이면 단계별 구조, 비교형이면 항목별 대조 구조를 택한다.

### 2. 출처 조사 및 수집
- WebSearch/WebFetch로 신뢰할 출처를 찾는다. 1차 자료(공식 발표, 원 통계, 원 논문)를 2차 매체보다 우선한다
- 각 출처에 `[S1]`, `[S2]` … ID를 부여하고, 제목·URL/출처·신뢰도(1차/2차)·추출한 핵심 사실을 기록한다
- 같은 사실을 2개 이상 출처가 뒷받침하면 모두 기록한다 (교차 검증력 ↑)
- 상충하는 정보는 한쪽을 버리지 말고 양쪽을 출처와 함께 남긴다

`_workspace/01_researcher_sources.md` 형식:
```
# 출처 목록: {주제}

## [S1] {출처 제목}
- 출처/URL: ...
- 신뢰도: 1차 | 2차
- 핵심 사실:
  - ...
  - ...
```

### 3. 개요 설계
수집한 사실을 검색 의도에 답하는 순서로 배열한다. 독자가 가장 알고 싶은 것을 앞에, 배경·심화를 뒤에 둔다.

각 섹션에 반드시 포함:
- 답할 질문 (이 섹션이 해결하는 독자의 의문)
- 핵심 메시지 (한 문장)
- 근거 출처 ID

`_workspace/01_researcher_outline.md` 형식:
```
# 작업 개요: {주제}
- 타깃 독자: ...
- 검색 의도: ...
- 권장 톤/분량: ...
- 조사 한계: {출처를 못 찾아 제외한 주제, 없으면 "없음"}

## 섹션 1: {H2 제목}
- 답할 질문: ...
- 핵심 메시지: ...
- 근거 출처: [S1], [S3]
### (선택) {H3 하위 제목}
- ...
```

### 4. 자체 점검
개요를 writer에게 넘기기 전 확인한다:
- 모든 섹션에 근거 출처 ID가 있는가? (출처 없는 섹션은 제외하거나 "조사 한계"에 기록)
- sources 파일의 모든 [Sx] ID가 개요 또는 한계 항목에서 참조되는가?
- 섹션 순서가 검색 의도에 답하는가?

## 후속 작업 (재실행)
이전 개요/출처 파일이 있으면 먼저 읽는다. editor나 사용자가 특정 섹션의 출처 보강을 요청하면 **그 섹션만** 조사·갱신하고 나머지 ID 체계는 보존한다. 새 주제면 처음부터 시작한다.

## 출력 요약
- `_workspace/01_researcher_sources.md`
- `_workspace/01_researcher_outline.md`
완료 시 writer에게 개요 경로와 주의할 핵심 사실을 SendMessage로 통지한다.
