# Render QA — 실제 렌더·로직 검증

"있는지"가 아니라 **"실제 픽셀에서 올바르게 보이고, 모든 경우에 답이 맞는지"**를 확인한다. 상상하지 말고 캡처해서 본다.

## 헤드리스 캡처 (Windows)

Chrome 또는 Edge headless로 PNG 캡처 후 Read로 직접 본다. **절대 경로**로 저장한다(상대 경로는 권한 거부될 수 있음).

```bash
CH="/c/Program Files/Google/Chrome/Application/chrome.exe"   # 또는 Edge msedge.exe
D="C:/Users/vamos/Desktop/코딩/수학 게임 만들기"
B="file:///C:/Users/vamos/Desktop/%EC%BD%94%EB%94%A9/%EC%88%98%ED%95%99%20%EA%B2%8C%EC%9E%84%20%EB%A7%8C%EB%93%A4%EA%B8%B0/index.html"
"$CH" --headless=new --disable-gpu --hide-scrollbars --force-device-scale-factor=1 \
  --window-size=900,1500 --virtual-time-budget=20000 \
  --screenshot="$D/_workspace/shots/home.png" "$B"
```

- 경로의 한글·공백은 URL 인코딩(`%EC%...`, `%20`).
- `--virtual-time-budget`은 타이머/애니메이션을 빠르게 진행시킨다. 단계를 거쳐야 하는 화면은 넉넉히(20000+).

## 단계까지 자동 진행해 캡처 (데모 훅)

받아내림 보조판 같은 "특정 단계"를 캡처하려면 frontend-builder에게 임시 데모 훅을 요청한다: `?demo=N&a=52&b=27` → `makeProblem` 고정 + `#nextBtn` N번 자동 클릭.

```
B + "?demo=6&a=52&b=27"   # 52−27의 일의 자리 가르기 단계까지 진행
```

검증이 끝나면 **데모 훅 제거**를 frontend-builder에 요청한다.

## 애니메이션 중간 캡처 주의

캡처가 흐릿하거나 비어 보이면 애니메이션 중간에 멈춘 것일 수 있다. `--virtual-time-budget`을 늘려 정착 후 재캡처한 뒤 판단한다. 한 번의 흐릿함으로 "버그"라 단정하지 않는다.

## 레이아웃 체크리스트

스크린샷에서 확인:
- [ ] 요소 겹침 없음 (마스코트·말풍선·보조판·세로셈이 서로 안 겹침)
- [ ] 한쪽 쏠림 없음 (보조판이 해당 자리 칸 아래 정렬되는가)
- [ ] 화면 밖 잘림 없음 (특히 오른쪽 끝 자리 아래 보조판)
- [ ] 마스코트가 보이고 표정이 상황에 맞음
- [ ] 글씨 크기·둥근 정도·여백이 디자인 토큰과 일치

## 산술 로직 검증 매트릭스

각 케이스를 데모 훅으로 끝까지 진행해 결과 셀과 보조판을 확인한다:

| 입력 | 기대 | 점검 |
|------|------|------|
| 52 − 27 | 25 | 일 받아내림, 7=2+5 → 12−2=10 → 10−5=5 |
| 423 − 180 | 243 | 십 받아내림, 보조판 십의 자리 아래 |
| 40 − 7 | 33 | 딱 10(가르기 없이 10−7) |
| 305 − 8 | 297 | 연쇄 받아내림(가운데 0) |
| 47 + 28 | 75 | 일 받아올림 |
| 99 + 1 | 100 | 받아올림 중첩(자리수 증가) |

**경계면 교차 비교:** 화면에 찍힌 결과 숫자가 `script.js`의 계산값과 일치하는지 함께 본다. 보이기만 하고 값이 틀리면 불합격.

## 정리

- 스크린샷은 `_workspace/shots/`에 저장, 리포트에서 경로로 참조.
- 검증 후 임시 캡처 파일·데모 훅 정리.
- 결함은 좌표·케이스·원인 추정과 함께 보고. 모호하면 사실(스크린샷+수치)만 보고하고 판단은 design-director/사용자에 맡긴다.
