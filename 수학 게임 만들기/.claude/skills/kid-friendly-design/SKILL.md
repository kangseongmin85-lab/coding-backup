# Kid-Friendly Design — 아이 친화 디자인 시스템

초등 저학년(만 8~9세) 학습 게임 "여우 선생님과 세로셈"의 디자인을 일관되게 만들고 검수한다. 목표는 **따뜻함 · 명료함 · 재미**. 세련됨이나 정보 밀도보다 아이가 "또 하고 싶다"고 느끼는 화면을 만든다.

## 디자인 철학 (왜 이렇게 하는가)

아이는 글보다 **색·모양·캐릭터·움직임**으로 먼저 이해한다. 그래서:
- **큰 글씨 · 둥근 모서리 · 밝은 색 · 살아있는 캐릭터**가 기본값이다. 작고 빽빽하고 회색인 화면은 아이를 밀어낸다.
- 색에는 **일관된 뜻**을 준다. 색이 의미를 가지면 아이는 글을 못 읽어도 구조를 읽는다.
- 움직임은 **개념을 보이게 하는 도구**다. 받아올림·받아내림·가르기가 "눈에 보이게" 한다. 장식적 움직임은 줄인다.

## 외부 디자인 참고 원칙 — 구조만, 톤은 아이답게

프로젝트에 기업용 디자인 파일(`DESIGN-cohere.md` 등)이 있어도 **그대로 입히지 않는다.** 기업용은 "절제·통제"가 목표라 아이용과 충돌한다. 빌릴 것과 버릴 것:

| 빌린다 (구조) | 버린다 (톤) |
|---------------|-------------|
| 흰 카드 + 둥근 모서리(16~24px) | 차가운 흑·딥그린·네이비 바탕 |
| 또렷한 타입 위계, 정돈된 여백 | 거대 모노스페이스의 무거운 분위기 |
| 얇은 테두리 중심의 가벼운 깊이 | "둥글지만 귀엽지 않게" 원칙 |
| 절제된 바탕 + 포인트 컬러 1개 | 색을 억제하는 무채색 지향 |

→ 결과: **구조는 깔끔하게, 색·캐릭터·움직임은 아이답게.** 포인트 컬러는 `DESIGN-cohere.md`의 coral(`#ff7759`)을 그대로 이어받아 따뜻함의 앵커로 쓴다.

## 색 시스템 — 의미 있는 색

세부 값은 `references/design-tokens.md`를 로드한다. 원칙:
- **일=파랑, 십=초록, 백=주황** — 자리값을 색으로 구분해 아이가 자리를 색으로 인지.
- **coral = 포인트·정답·강조** — 가장 따뜻한 색을 "잘했다/핵심"에 쓴다.
- **보라 = 뺄셈 보조 강조** — 뺄셈 맥락의 강조어.
- 바탕은 흰색에 가깝되 **아주 옅은 따뜻한 그라데이션**으로 차갑지 않게.
- 한 화면에 강한 색은 2~3개까지. 나머지는 잉크/회색으로 양보해 핵심이 튀게 한다.

## 타이포 — 크고 또렷하게

- 숫자(세로셈)는 화면의 주인공. 가장 크게(약 3rem), `tabular-nums`로 자릿수 정렬.
- 위계: 로고 > 화면 제목 > 말풍선 본문 > 캡션. 굵기보다 **크기·색·여백**으로 위계를 만든다.
- 한국어 친화 폰트 스택(Pretendard → 시스템). 아이가 읽기 쉬운 둥근 산세리프.

## 여우 선생님 마스코트

아이가 "함께 푸는 친구"로 느끼게 하는 핵심 장치. 규칙:
- **항상 같은 캐릭터**(여우)로 일관. 홈에서 크게 인사, 학습 중엔 말풍선 옆에서 거든다.
- **표정 상태**로 감정을 준다:
  | 상태 | 표정 | 언제 |
  |------|------|------|
  | 기본 | 뜬 눈, 옅은 미소 | 문제 진행 중 |
  | happy | 웃는 눈(아치), 깡총 점프 | 정답·단계 완성·축하 배너 |
- 말풍선은 **여우가 말하는 것처럼** 꼬리를 여우 쪽으로 둔다.
- SVG로 그려 선명하고 가볍게. 표정은 요소 show/hide로 전환(이미지 교체 불필요).
- 과하지 않게: 표정 변화는 의미 있는 순간(정답·완성)에만. 매 순간 들썩이면 산만하다.

## 모션 — 부드럽고 친근하게

움직임의 "느낌"이 친근함을 좌우한다:
- **이징은 살짝 튀게**(`cubic-bezier(.2,1.5,.4,1)` 류) — 숫자가 "톡" 나타나면 생동감이 생긴다. 단, 과한 바운스는 어지럽다.
- **속도는 따라올 수 있게.** 단계 전이는 0.3~0.5s. 너무 빠르면 못 보고, 너무 느리면 지친다.
- 등장은 작게→제자리(scale/translateY), 강조는 살짝 흔들거나 빛나게.
- 마스코트엔 아주 느린 idle bob(3s)로 "살아있음"을 준다.
- 효과(별·축하 배너)는 정답·완성에만. 보상의 희소성이 동기를 만든다.

## 레이아웃 — 중심에 핵심, 손이 닿는 곳에 도구

- **세로셈을 화면 세로 중앙**에 크게. 주변은 비워 시선이 모이게.
- 터치펜 사용 → 도구 버튼은 크게(터치 타깃 ≥ 48px), 숫자와 겹치지 않게 별도 줄에.
- 보조 설명(가르기 등)은 **관련된 자리 바로 아래**에 연결선으로 이어 맥락을 끊지 않는다.

## 친근함 검수 체크리스트 (디자인 합격 기준)

화면이 아래를 만족하는지 render-qa 스크린샷으로 확인한다:
- [ ] 숫자/버튼 글씨가 충분히 큰가 (멀리서도 읽히는가)
- [ ] 색이 의미와 일치하는가 (일=파랑, 십=초록, 정답=coral)
- [ ] 마스코트가 보이고 표정이 상황에 맞는가
- [ ] 요소가 겹치거나 한쪽으로 쏠리거나 잘리지 않았는가
- [ ] 한 화면에 강한 색이 2~3개 이내인가 (정신없지 않은가)
- [ ] 둥근 모서리·여백이 일관적인가
- [ ] 움직임이 개념을 돕는가, 그냥 장식인가

## 검수 절차

1. design-director가 스펙(토큰·표정·모션·레이아웃)을 정한다.
2. frontend-builder가 구현한다.
3. render-qa가 캡처한다.
4. 위 체크리스트로 합격/불합격 판단. 불합격이면 **구체 수치로** 수정 지시(예: "여우 12px 키우고, 말풍선 꼬리 4px 위로").

## 산출물

- `_workspace/{phase}_design-director_spec.md`: 토큰 표 + 마스코트 상태 + 모션 파라미터 + 레이아웃 규칙 + 수정 지시.
- 디자인 결정의 근거는 항상 실제 스크린샷. 상상으로 합격시키지 않는다.
