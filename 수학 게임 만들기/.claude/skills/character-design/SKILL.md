# Character Design — 살아있는 아이 친화 캐릭터 만들기

초등 저학년 학습 게임 "여우 선생님과 세로셈"의 캐릭터를 **매력 있고 살아있게** 설계·개발한다. 목표는 아이가 "이 친구랑 같이 공부하고 싶다"고 느끼는 캐릭터다. 색·모션의 전역 톤은 `kid-friendly-design`을 따르고, 이 스킬은 **캐릭터 그 자체**(매력·성격·표정·SVG 제작)에 집중한다.

## "단순해 보인다"의 진짜 원인 (왜)

"여우가 단순하다/흥미 없다"는 선이 적어서가 아니라 보통 네 가지가 비어서다. 선을 늘리기 전에 이 4축을 먼저 채운다:

| 빈 곳 | 증상 | 채우는 법 |
|-------|------|-----------|
| **실루엣** | 윤곽이 평범, 다른 캐릭터와 안 구별됨 | 귀·볼·꼬리 등 고유 형태를 과장. 검은 실루엣만으로 알아보게 |
| **표정 폭** | 늘 같은 얼굴 | 감정 상태별 표정 시트(아래). 눈·입·눈썹을 바꿔 감정을 분명히 |
| **성격 단서** | 누구인지 안 느껴짐 | 기본 표정·포즈·소품에 성격을 심는다(다정한 미소, 살짝 기운 고개) |
| **디테일** | 밋밋·납작 | 눈 하이라이트, 볼터치, 눈썹, 안쪽 귀, 살짝의 음영 — **적게, 의미 있게** |

→ 핵심: **선을 늘려 복잡하게 만들지 말고, 매력 요소를 채워 "살아있게"** 만든다.

## 매력(Appeal) 원리

- **형태 언어:** 둥근 형태 = 친근/안전. 날카로움은 최소. 아이 캐릭터는 **큰 머리·큰 눈·작은 코·통통한 볼**(유아 비율)이 귀여움의 핵심.
- **비율:** 머리가 몸/얼굴에서 크게. 눈은 얼굴의 중앙~아래, 둘 사이 간격 넉넉히(어릴수록 멀고 아래).
- **실루엣 테스트:** 색을 다 지우고 윤곽만 봤을 때 알아보면 합격. 안 되면 형태부터 고친다.
- **비대칭으로 생동:** 고개를 살짝 기울이거나 한쪽 눈썹을 올리면 "살아있는" 느낌. 완벽한 좌우대칭은 인형처럼 굳어 보인다.
- **디테일의 절제:** 눈 하이라이트 1~2개, 볼터치, 눈썹 정도. 과한 무늬·그림자는 아이 화면에서 산만.

## 성격 부여

캐릭터는 "기능"이 아니라 "친구"다. 여우 선생님의 성격을 한 줄로 못 박고, 그것을 기본 표정·포즈·소품으로 표현한다.

- 예) **여우 선생님 = 다정하고 살짝 장난기 있는 길잡이.** → 기본은 옅은 미소 + 호기심 어린 눈, 정답엔 함께 신나함, 오답엔 놀리지 않고 "괜찮아 같이 해보자" 표정.
- 성격은 **말풍선 문장(math-pedagogue/디자인과 협의)** 과도 일관돼야 한다. 생김새와 말투가 따로 놀면 캐릭터가 깨진다.

## 표정 시트 (Expression Sheet) — 캐릭터의 생명

기존 코드는 `eyes-open`/`eyes-happy` 두 표정을 `mood` 클래스로 토글한다. 이를 **감정 세트로 확장**한다. 각 표정은 SVG 요소 그룹의 show/hide로 만든다(이미지 교체 없음 → 가볍고 선명).

권장 최소 세트 (게임 이벤트와 매핑):

| mood | 언제 | 얼굴 단서 |
|------|------|-----------|
| `idle`(기본) | 문제 진행 중 | 뜬 눈 + 옅은 미소 + 느린 bob |
| `happy` | 정답·단계 완성·축하 | 웃는 아치 눈 + 입 벌린 미소 + 깡총 hop |
| `think` | 문제를 살필 때(살펴보기 단계) | 눈동자 위로 + 한쪽 눈썹 ↑ + 작은 입 + (소품: 물음표) |
| `cheer` | 완성/레벨업/마을 완성 | 반짝 눈 + 활짝 + 팔/소품 들기 + 별 |
| `oops` | 오답 | 눈썹 八자 + 작은 입 + 살짝 갸웃 (놀리지 않고 안쓰럽게/응원) |

> 표정 추가의 핵심은 **눈·눈썹·입**이다. 이 셋만 바꿔도 감정이 분명해진다. 모든 표정을 한 번에 만들지 말고, 이벤트가 있는 표정부터 우선한다.

## 캐릭터 캐스트 (선택)

주인공 여우 외에 보조 친구를 더할 때는 "한 세계관"을 지킨다:
- **공유:** 선 굵기, 눈/머리 비율, 팔레트 범위, 그림체. (토끼 친구를 더해도 같은 손에서 나온 듯)
- **구별:** 종(여우/토끼/곰)·색·실루엣·성격으로 차별. 역할을 주면(응원단·문제 출제자) 등장 이유가 생긴다.
- 과용 금지: 화면당 강한 캐릭터는 1~2명. 주인공이 묻히면 안 된다.

## 코드 호환 SVG 제작 (드롭인)

새 캐릭터/표정은 기존 구현에 그대로 꽂혀야 한다. 규약:
- `FOX_SVG` 문자열을 대체/확장. `viewBox`는 기존(예: `0 0 120 124`) 비율을 유지해 레이아웃이 안 튀게 한다.
- 레이어 순서: 꼬리/뒤 → 귀 → 머리 → 주둥이/볼 → **표정 그룹(눈·눈썹·입)** → 코 → 볼터치 → 소품.
- 표정은 그룹 클래스로: `.eyes-open`/`.eyes-happy`처럼 mood별 그룹을 두고 CSS가 show/hide. 새 mood는 `setMood('think')` → `.mascot.mood-think .grp-think{display:block}` 패턴.
- `paintFoxes()`가 `[data-fox]`에 주입하므로 마크업 중복 없음. `setMood()`가 `#mascot` 클래스 토글.
- **상세 좌표·레이어·확장 예시(눈썹/추가 mood 포함)는 `references/svg-anatomy.md`를 로드.**

## 모션 연계

표정과 움직임은 한 몸이다. 전역 모션 규칙(`kid-friendly-design`)과 일치시킨다:
- idle: 아주 느린 bob(3s)로 "살아있음".
- happy: 짧은 hop(0.5s). 등장: 작게→제자리.
- 표정 전환은 **즉각**(감정은 바로 읽혀야). 보상 표정(happy/cheer)은 정답·완성에만(희소성=보상감).

## 검수 체크리스트 (합격 기준 — render-qa 스크린샷으로)

- [ ] 실루엣만으로 알아보는가
- [ ] 표정이 감정을 분명히 전하는가(idle/happy 최소, 가능하면 think/oops)
- [ ] 더 이상 "밋밋/단순"하지 않은가 — 4축(실루엣·표정·성격·디테일)이 채워졌는가
- [ ] 성격이 느껴지는가(생김새와 말투가 일관된가)
- [ ] `setMood` 토글로 표정이 실제 전환되는가(콘솔 에러 없이)
- [ ] 팔레트·선 굵기·비율이 기존 세계관과 일치하는가
- [ ] 캐스트 추가 시 주인공이 묻히지 않는가
