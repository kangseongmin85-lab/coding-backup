## 신규 발견 — 인계문서에 없던 문제

### (E) 중복 검증이 파이프라인을 사실상 멈추고 있음 · 우선순위 높음

`main.py`:

```python
recent = " ".join(titles[:80])          # 노션 하위페이지 제목 80개를 한 덩어리 문자열로
fresh  = [i for i in issues if i.keyword not in recent]   # 부분문자열 검사
```

키워드가 **제목 80개를 이어붙인 문자열 어딘가에 포함되기만 하면** 중복으로 간주된다.
- 한 번 다룬 키워드는 기간 제한 없이 영구 차단
- `급락`, `코스피`, `연준` 같이 매일 반복되는 핵심 키워드가 가장 먼저 영구 차단됨
- `com`, `kr` 등 (B)의 쓰레기 키워드도 차단 목록에 들어가 오탐을 키움

실제로 최근 회차 상당수가 48초 내외로 `새로운 이슈 없음(전부 기존 페이지와 중복) — API 호출 없이 종료`.
가장 최근 회차(32243277838, 10:33Z)도 이 경로로 종료.

→ **크레딧을 충전해도 이 로직 때문에 글이 안 써질 수 있음.** (A) 다음 순위로 다뤄야 함.
수정 방향: 제목에서 키워드 필드를 정확히 파싱해 집합 비교 + 최근 N일 윈도우만 차단.

## 로컬 배치 관련 주의

`x 수익화/issue2content` 는 자체 git 저장소이므로, 상위 `코딩` 저장소의 `자동백업.ps1`(`git add -A`)이
이를 **gitlink(서브모듈 항목)로 커밋**하게 된다. `.gitmodules`가 없어 백업본에는 코드가 안 담기고
깨진 참조만 남는다. `코딩/.gitignore` 에 `x 수익화/issue2content/` 추가 권장
(이 저장소는 GitHub에 따로 백업되므로 이중 백업 불필요).
