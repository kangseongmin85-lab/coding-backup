# Roleplay Meeting — 미팅 시뮬레이션

실제 업무 미팅을 시뮬레이션한다. 핵심 설계: **상대역 대사를 텍스트가 아니라 오디오로 먼저 전달**한다. 사용자의 약점이 듣기이므로, 롤플레이가 곧 듣기 훈련이 되어야 실전(못 알아들으면 대화 단절)을 재현·극복할 수 있다.

## 시나리오 카탈로그

| 시나리오 | 상대역 | 예시 상황 |
|----------|--------|----------|
| `cro-kickoff` | CRO 프로젝트 리드 | 위탁 실험 킥오프, 범위·일정 합의 |
| `cro-protocol` | CRO 사이언티스트 | 프로토콜 세부 논의, 조건 변경 요청 |
| `cro-results-review` | CRO 프로젝트 리드 | 중간/최종 결과 리뷰, 이상 데이터 질의 |
| `cro-negotiation` | CRO 어카운트 매니저 | 일정 지연·비용 협상, 품질 이슈 제기 |
| `asset-evaluation` | 파트너사 BD/과학자 | 에셋 평가 Q&A, 데이터 패키지 검토 |
| `licensing` | 파트너사 BD | 라이선싱 조건·마일스톤 디스커션 |
| `internal-update` | 글로벌 본사 동료 | 프로젝트 업데이트, 리스크 보고 |

사용자가 시나리오를 안 정하면 위에서 2~3개를 추천한다. 사용자가 "내일 실제로 이런 미팅 있어"라고 하면 그 상황을 그대로 시나리오로 만든다 — 실전 리허설이 가장 좋은 훈련이다.

## 진행 프로토콜

0. **학습 문장 시드 (이 롤플레이의 핵심 설계)**: 시작 전 `data/sentences.json`을 읽어 사용자가 배운 문장을 파악하고, 시나리오에 맞는 문장을 골라 **상대역 대사를 그 문장들이 자연스러운 응답이 되도록** 설계한다 — 즉 배운 문장을 대화 곳곳에 배치해 실제로 입으로 써 보게 한다 (예: 상대역이 일정 변경을 흘리면 사용자가 `Let me make sure I got that right — ~?`로 확인하도록, 협상 국면을 열어 `Would you be open to ~?`가 나오도록). 생존 표현(`Sorry, could you say that again?`, `you're breaking up`, `I'm not sure I follow` 등)은 사용자가 오디오를 못 알아들을 때 쓰도록 유도한다. 시나리오당 학습 문장 3~6개가 자연스럽게 등장하도록 턴을 구성한다.
1. **설정**: 시나리오, 상대역 이름/역할, 상황 브리핑(한국어 2~3줄), 사용자의 목표(예: "지연 사유를 듣고 새 일정을 합의한다")를 제시한다.
2. **상대역 턴 — 오디오 먼저**:
   - 대사를 작성하되 화면에 출력하지 않는다.
   - `audio/roleplay/`에 생성 후 재생: `python .claude/skills/multi-accent-audio/scripts/generate_audio.py --text "대사" --id turn01 --voices us-m --out audio/roleplay` → `play_audio.ps1`로 재생. 한 세션 동안 상대역 음성(악센트·성별)은 고정한다 — 실제 미팅처럼.
   - 사용자가 못 알아들으면: "again" → 재재생, 두 번째도 못 알아들으면 느린 버전(`--rate=-15%`) 생성·재생, 그래도 안 되면 텍스트 공개 후 계속. **못 알아듣는 상황 자체가 훈련이다** — "Sorry, could you say that again?"을 영어로 말해보도록 유도한다.
3. **사용자 턴**: 사용자가 영어 텍스트로 응답한다. 문법이 틀려도 **대화 흐름을 끊지 않는다** — 즉시 교정하지 말고 메모해 두고 대화를 이어간다. 실전에서 중요한 건 흐름이다. 단, 의미가 통하지 않을 때만 상대역으로서 자연스럽게 되묻는다 ("Sorry, do you mean ~?").
4. **턴 수**: 6~10턴 내외. 사용자가 목표를 달성하거나 지치면 마무리.
5. **종료 피드백** (한국어):
   - 잘한 표현 2~3개 (그대로 칭찬)
   - 어색했던 표현 → 원어민이라면 이렇게: before/after 비교
   - **배운 문장 사용 현황**: 이번 대화에서 실제로 쓴 학습 문장과, 쓸 수 있었는데 놓친 학습 문장을 함께 짚어준다 (놓친 문장은 다음 복습 우선순위로).
   - 이 시나리오에서 외울 가치가 있는 핵심 표현 3~5개 → "sentences.json에 추가할까요?" 제안, 동의하면 lesson-builder 호출 없이 직접 sentence-pack 스킬 규칙대로 등록 + 오디오 생성
6. **기록**: `data/sessions/{YYYY-MM-DD}_roleplay.md` — 시나리오, 대화 전문, 피드백, 추가된 문장 id. 추가로 (`study-record` 스킬 규칙): 피드백에서 알려준 새 단어/표현을 `data/vocab.json`에 등록하고, `data/study_log.json`에 세션 엔트리(mode: roleplay, turns, scenario, 새 단어, note)를 추가한다.

## 난이도 조절

- 초반: 상대역 대사 8~12단어, 한 턴에 한 가지 내용만.
- 사용자가 잘 따라오면: 대사를 15~20단어로, 두 가지 내용(정보 + 질문)을 한 턴에 섞는다 — 실제 미팅의 정보 밀도에 근접.
- `audio/roleplay/`의 턴 파일은 세션 시작 시 비운다 (이전 세션 잔여물 제거).
