# Listening Drill — 받아쓰기 훈련

사용자는 간단한 문장도 못 알아들어 대화가 끊기는 것이 최대 약점이다. 이 드릴의 목적은 **소리와 의미를 직접 연결하는 회로**를 만드는 것이다.

## 철칙: 텍스트를 먼저 보여주지 않는다

오디오를 재생하기 전에 문장 텍스트를 화면에 출력하면 안 된다. 텍스트를 먼저 보면 사용자는 듣기가 아니라 **읽은 내용을 확인**하게 되어 훈련 효과가 사라진다. 문장 선택·재생 안내 시에도 id와 "재생합니다"만 표시한다. 정답 텍스트는 채점·해설이 끝난 뒤에만 공개한다.

## 세션 절차 (문장당)

1. **문장 선택**: 복습 큐(`srs.next_review <= 오늘`) 우선, 신규 문장 혼합. 한 세션 5~8문장. 사용자가 특정 문장/주제를 지정하면 그것을 따른다.
2. **재생**: 악센트는 문장마다 순환/랜덤 (약한 악센트 우선 — `listening.weak_accents` 참조). 첫 시도는 보통 속도.
   ```powershell
   powershell -ExecutionPolicy Bypass -File .claude/skills/multi-accent-audio/scripts/play_audio.ps1 -Path audio/{id}_{voice}.mp3
   ```
3. **받아쓰기**: "들은 대로 입력해 주세요 (들리는 만큼만, 한 번 더 듣고 싶으면 'again')". again 요청 시 같은 속도 1회 → 그다음부터 `_slow` 버전.
4. **채점**: 단어 단위 비교. 대소문자·구두점 무시, 들리는 대로 쓴 동음 표기는 관대하게. 결과를 다음 형식으로:
   - 맞은 단어는 그대로, 틀림/누락은 **굵게** 표시한 정답 문장
   - 정답률 (맞은 단어 / 전체 단어)
5. **해설 — 왜 안 들렸는가**: 놓친 부분을 connected speech 관점에서 설명한다. 이것이 이 드릴의 핵심 가치다:
   - **연음(linking)**: "walk me through" → /wɔːkmiθruː/처럼 붙어서 들림
   - **약형(weak forms)**: of/to/for/and/can은 강세 없이 /əv/, /tə/처럼 뭉개짐
   - **flap t** (미국): "data" → "dæɾə"
   - **자음 탈락/동화**: "last batch" → t 거의 안 들림
   - 한국어로, 해당 문장의 실제 소리를 들리는 대로 표기해 가며 설명한다.
6. **재청취 강화**: 해설 후 같은 문장을 느린 버전 → 보통 속도 순으로 다시 재생해, 이제 들리는지 확인한다.
7. **악센트 비교** (여유 있을 때): 같은 문장을 다른 악센트로 재생하고 차이 포인트 1~2개를 짚는다.
8. **공개 + 쉐도잉**: 정답 영어 + 한국어 뜻 공개. "오디오를 따라 3번 소리 내어 말해보세요" 권유 (말하기 연결 — 최종 목표가 스피킹이므로 생략하지 않는다).

## 기록 (세션 종료 시)

1. `data/sentences.json` 갱신 — 각 문장의:
   - `listening.attempts` +1, 정답률 80% 이상이면 `correct` +1
   - 놓친 단어를 `listening.missed_words`에 append
   - 정답률 50% 미만이었던 악센트를 `listening.weak_accents`에 추가 (중복 제거)
   - SRS 갱신은 `review-srs` 스킬 규칙을 따름 (받아쓰기 = 복습으로 인정)
2. `data/sessions/{YYYY-MM-DD}_dictation.md` 로그: 문장별 (id, 악센트, 정답률, 놓친 단어, 해설 키워드)
3. **단어장 + 공부 이력** (`study-record` 스킬 규칙):
   - 놓친 단어 중 **뜻 자체를 모르는 단어**만 `data/vocab.json`에 등록 (아는데 못 들은 단어는 missed_words로 충분). 애매하면 사용자에게 확인.
   - `data/study_log.json`에 세션 엔트리 추가 (mode: dictation, 문장 id, attempted/passed, 새 단어, 핵심 관찰 note)

## 난이도 조절

- 연속으로 정답률이 낮으면(2문장 연속 50% 미만): 짧은 문장으로 전환하거나 첫 재생부터 `_slow` 사용. 사용자를 좌절시키지 않는 것이 계속하게 만드는 조건이다.
- 정답률이 높으면(90%+): 빠른 버전(`_fast`) 도전 또는 긴 문장 제안.
