# English Study — 학습 세션 오케스트레이터

바이오 R&D 프로젝트 매니저인 사용자의 비즈니스 영어 학습을 조율한다. 사용자의 최종 목표는 **상대방의 말을 알아듣고 유창하게 자기 생각을 말하는 것**이며, 최대 약점은 **듣기**다. 따라서 모든 모드에서 오디오(듣기)를 우선한다.

**실행 모드: 하이브리드**
- 인터랙티브 훈련(받아쓰기, 롤플레이, 복습)은 **메인 세션이 스킬을 직접 사용**한다. 서브 에이전트는 사용자와 실시간 대화할 수 없기 때문이다.
- 콘텐츠 생성(문장팩+오디오)과 기록 분석은 **서브 에이전트**(lesson-builder, progress-analyst)에 위임한다. 결과만 받으면 되는 작업이다.

## 학습 앱 (브라우저)

받아쓰기·복습·단어장·이력 조회는 로컬 웹앱으로도 할 수 있다. "앱 켜줘", "앱으로 공부할래" 요청 시:

```powershell
python app/server.py   # 백그라운드 실행 후 http://localhost:8770 안내
```

앱은 `data/*.json`을 직접 읽고 쓰므로 Claude 세션과 기록이 공유된다. 역할 분담: **앱** = 반복 훈련(받아쓰기/SRS/단어장/이력) + 문장 카드 넘기기 + 앱 내 문장 추가(`/api/add_sentence`가 `claude -p`로 번역·notes 생성 + 오디오 생성) + YouGlish 영상 연동, **Claude 세션** = 코칭(문장팩 생성, 롤플레이, 약점 분석). 앱이 보여주는 듣기 해설은 `sentences.json`의 `notes` 필드이므로, 문장 등록 시 notes를 반드시 채운다 (sentence-pack 스킬 규칙). 앱에서 추가된 문장에 notes가 비어 있으면(Claude CLI 실패 폴백) 세션에서 발견 시 채워준다.

## Phase 0: 컨텍스트 확인

세션 시작 시 항상 확인한다:

1. `data/sentences.json` 읽기 — 없으면 **초기 실행**: 사용자에게 첫 문장팩 주제를 묻고 lesson-builder를 호출한다.
2. 있으면 복습 큐 계산 (`srs.next_review <= 오늘`인 문장 수)를 세션 인사에 포함한다. 예: "오늘 복습할 문장이 4개 있어요."
3. 사용자 요청이 부분 작업이면(예: "s003 발음 다시 들려줘") 전체 워크플로우 없이 해당 작업만 수행한다.

## 모드 라우팅

| 사용자 요청 | 모드 | 실행 방식 |
|------------|------|----------|
| 문장 추가, 문장팩 생성, "이 문장 외우고 싶어" | 문장팩 | **서브 에이전트** `lesson-builder` (model: opus) 호출 |
| 듣기 연습, 받아쓰기, 딕테이션 | 듣기 훈련 | 메인 세션 + `listening-drill` 스킬 |
| 롤플레이, 미팅 연습, 회화 연습 | 롤플레이 | 메인 세션 + `roleplay-meeting` 스킬 |
| 복습, "오늘 영어 하자" (복습 큐 있을 때) | 복습 | 메인 세션 + `review-srs` 스킬 |
| 학습 현황, 약점 분석, "나 뭐가 약해?" | 분석 | **서브 에이전트** `progress-analyst` (model: opus) 호출 |
| 단어장, "이 단어 기억해줘", 공부 이력 조회 | 기록 | 메인 세션 + `study-record` 스킬 |
| 모호한 요청 ("영어공부 하자") | 메뉴 | 복습 큐 안내 + 모드 선택지 제시 |

서브 에이전트 호출 시 반드시 `model: "opus"`를 명시한다.

## 데이터 전달 (파일 기반)

| 파일 | 역할 |
|------|------|
| `data/sentences.json` | 단일 진실 원천: 모든 학습 문장 + SRS 상태 + 받아쓰기 기록 |
| `audio/{id}_{voice}.mp3` | 문장별 악센트 오디오 (`_slow` 접미사 = 느린 버전) |
| `audio/roleplay/` | 롤플레이 턴별 임시 오디오 |
| `data/vocab.json` | 단어장 — 뜻을 몰랐던 단어/표현 (`study-record` 스킬이 기준) |
| `data/study_log.json` | 누적 공부 이력 — 세션당 1엔트리 (`study-record` 스킬이 기준) |
| `data/sessions/{날짜}_{모드}.md` | 세션 상세 로그 (받아쓰기 결과, 롤플레이 피드백) |
| `_workspace/analysis_*.md` | progress-analyst의 약점 리포트 |

## 에러 핸들링

| 에러 | 대응 |
|------|------|
| 오디오 생성 실패 (edge-tts 네트워크) | 1회 재시도. 재실패 시 문장만 저장하고 사용자에게 알린 후 진행 |
| 재생할 오디오 파일 없음 | 즉석에서 `generate_audio.py`로 생성 후 재생 |
| `sentences.json` 파싱 실패 | `.bak`으로 백업 후 사용자에게 보고. 임의 복구 금지 |
| 받아쓰기 중 사용자가 포기 | 정답 공개 + 해설 후 해당 문장을 실패로 기록하고 다음으로 |

## 세션 종료

1. 세션 로그를 `data/sessions/`에 기록한다 (해당 스킬의 형식대로).
2. SRS 상태를 갱신한다 (`review-srs` 규칙).
3. **공부 이력을 남긴다** — `data/study_log.json`에 세션 엔트리 추가, 세션 중 발견한 새 단어는 `data/vocab.json`에 등록 (`study-record` 스킬 규칙). 어떤 모드든 예외 없이.
4. 가볍게 피드백 기회를 제공한다: "오늘 훈련에서 바꾸고 싶은 점 있어요?" — 피드백이 오면 하네스 진화 대상(스킬/에이전트 수정)인지 판단하고 CLAUDE.md 변경 이력에 기록한다.

## 테스트 시나리오

**정상 흐름**: "영어공부 하자" → sentences.json 확인, 복습 큐 3개 안내 → 사용자가 "듣기 연습" 선택 → listening-drill 진행 (오디오 재생 → 받아쓰기 → 채점 → 해설) → 세션 로그 + SRS 갱신 → 피드백 질문.

**에러 흐름**: 받아쓰기 중 `audio/s004_gb-f.mp3` 누락 발견 → generate_audio.py로 즉석 생성 → 생성 실패(네트워크) → 1회 재시도 → 성공 시 계속, 실패 시 다른 문장으로 대체하고 사용자에게 알림.
